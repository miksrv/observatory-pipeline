---
name: api_client mock patterns
description: How to correctly mock httpx.AsyncClient as a context manager in api_client tests, and the inner/outer function pattern for tenacity retry + safe return
type: feedback
---

`api_client/client.py` is now the `api_client` package itself, split by REST resource directly into `api_client/frames.py`/`sources.py`/`anomalies.py`/`tasks.py`/`settings.py` plus an internal `_shared.py` (retry decorator, `AsyncClient` factory, batch-response normalization) — see CLAUDE.md. There is **no** intermediate `client` submodule/directory — that was tried and then deliberately collapsed away since nothing needed the extra nesting. `api_client/__init__.py` re-exports every public function AND does its own `import httpx`, so every call site elsewhere in this codebase does a plain `import api_client; api_client.post_frame(...)` (not `from api_client import client as api_client` — that's the pre-collapse form, now gone).

For testing, patch `api_client.httpx.AsyncClient` (not `httpx.AsyncClient`) using a `MagicMock` whose `return_value.__aenter__` is an `AsyncMock` returning the mock client, and `__aexit__` is an `AsyncMock` returning `False`. This works because `unittest.mock.patch`'s string-target resolution falls back to `getattr(api_client, "httpx")` — which the package's own `__init__.py` import satisfies — regardless of which submodule's `_make_client()` actually calls `httpx.AsyncClient()` at runtime (all submodules share the one `httpx` module object).

The retry-vs-safe-return design uses a private `_foo_with_retry` inner function decorated with `@_retry`, and a public `foo` outer function in the SAME submodule that calls the inner and catches `_RETRYABLE` exceptions to return `None`/`[]` instead of propagating. **`patch.object(api_client, "_foo_with_retry", ...)` does NOT work** — `foo`'s global lookup of `_foo_with_retry` resolves against its own submodule's namespace (e.g. `api_client.sources`), not the top-level package's `__init__.py` namespace, even though the package re-exports `foo` itself. Tests for "silent on error" must import the specific submodule (`from api_client import sources as _sources_module`, etc.) and patch `_foo_with_retry` on THAT object instead: `patch.object(_sources_module, "_foo_with_retry", AsyncMock(side_effect=exc))`.

**Why:** respx is not installed; unittest.mock is the only option. The inner/outer split lets tenacity retry the I/O path while the public API never raises, satisfying the "must not crash the pipeline" requirement. The submodule-patching gotcha above is a general Python fact (a function's free-variable lookup always uses its own `__globals__`, i.e. the module it was defined in — re-importing/re-exporting a name elsewhere doesn't change that), not specific to this codebase — see `feedback_module_to_package_split.md` for the generalized version of this rule (and two others) distilled after also applying it to `modules/anomaly_detector.py`.

**How to apply:** Whenever writing or reviewing api_client tests, use the `_patch_client` contextmanager pattern from test_api_client.py. For exhausted-retry tests, patch the inner `_*_with_retry` function on the specific submodule object it's actually defined in (import that submodule under an alias first: `from api_client import <resource> as _<resource>_module`), not on the top-level `api_client` package.
